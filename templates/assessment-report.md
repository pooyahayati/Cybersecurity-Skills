# Security assessment report

Template only. Replace prompts with observed facts; do not treat this file as an
assessment result. Keep sensitive evidence in an authorized private location.

## Decision and next actions

State the scoped conclusion, highest-priority actions, customer impact, responsible
owner and what is still blocked. Separate security, capacity and recovery outcomes.

## Scope and execution identity

Record target, source revision, deployed artifact/environment, observation time,
roles/accounts, authorized effects and limits. Record current component receipts
and limitations; never include credentials or access-bearing URLs.

## Coverage

| Control and version | Surface/environment | State | Evidence | Limitation/reason |
|---|---|---|---|---|

## Findings

For each finding: stable ID; plain-language title; affected location; actor and
prerequisites; customer impact; severity with rationale; confidence with rationale;
disposition; evidence type and references; counterevidence; proposed fix; responsible
owner; verification steps; remediation state; residual risk.

## Remediation and verification

State actual changes and tests, protected-state outcomes, legitimate-flow results,
related variants and environment-specific verification. Distinguish proposed work
from executed work and source changes from deployed fixes.

## Unresolved coverage and handoff

List inaccessible surfaces, unavailable modules, stale or failed evidence, required
next actions and any explicit risk acceptance. Do not close unknowns as false positives.
