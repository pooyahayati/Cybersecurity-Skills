# Deployed web and API assessment

Bind exact targets, environment, routes, accounts, allowed effects and request
budgets before requests. Passive analysis and crawling still contact a service.
Follow only in-scope redirects and resources; do not expand to linked hosts.

Map accessible routes and correlate source/configuration evidence when available.
Review transport, headers, browser state, cookies, CORS, caches, error disclosure,
exposed files/admin routes, uploads and API behavior. Compare ownership and role
boundaries with synthetic identities instead of relying only on anonymous scans.

Use selected reviewed dynamic checks. Active payloads, templates, fuzzing and
resource-heavy discovery require the appropriate scope. Bound retries and request
aggregation across tools. Do not send customer data or authenticated traffic to
third-party analysis services automatically.

Return sanitized requests/observations and the actual environment identity. A
status code alone does not prove disclosure or successful protection. URL-only
assessment must state unavailable source and infrastructure coverage explicitly.
