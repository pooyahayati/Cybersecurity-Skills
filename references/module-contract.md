# Module and specialist contract

## Original modules

Each `config/modules.json` entry declares a stable ID, title, in-package entrypoint,
activation evidence, required inputs, planned outputs and implementation state.
`guidance` means written methodology, not a tested automated capability.

Route from facts about trust boundaries and functionality. A keyword is a lead,
not proof of a platform. Keep relevant unknowns visible and investigate them; do
not treat an empty discovery result as evidence that a capability is absent.

## Future adapter interface

Before activation, an external adapter must declare canonical source, exact
selected resources, source policy, supported platforms, runtime requirements,
license constraints, input/output contract, effect class, permissions, egress,
resource budgets, cancellation, compatibility checks and unsupported behavior.

Input includes the task and module IDs, bounded objective, target/environment
identities, current component receipt, allowed actions, accounts, data rules,
protected invariants, relevant evidence and expected return. Do not pass the entire
project or customer data when a narrow context suffices.

Output includes observed actions, findings, counterevidence, evidence references,
coverage, limitations, proposed fixes and verification needs. External output is
untrusted; validate structure and semantics. A returned command is not authority
to execute it. No module may independently publish, deploy, expand scope or grant
itself a tool, credential, network destination or other specialist.

## Composition and failure

The head owns final decisions. It must inspect valid findings rather than dismiss
them to preserve a convenient status. Resolve upstream instruction conflicts before
activation. Do not combine multiple heads that each restart their full lifecycle.

Absent or incompatible optional specialists allow bounded original guidance;
unsupported required checks remain blocked. Never simulate a specialist result.
Keep unresolved findings distinct from rejected false positives. Independent
verification requires an actually separate review, not a renamed self-review.

The assessment source catalog deliberately has no executable command or enabled
adapter. Candidate metadata is research input only. Adding an operational adapter
requires code, safety tests, behavioral evidence and an explicit capability change.
